# RealPixelArt Web

纯前端像素画恢复与普通图片像素化工具。页面和算法都在浏览器内执行，图片不会上传；没有后端、数据库、远程推理或图像处理 API。所有运行资源均包含在这个目录中，可独立部署到普通静态托管。

点击左上角标题或右下角带 GitHub 图标的悬浮按钮，可在新标签页打开项目仓库，保留当前处理状态。按钮适配明暗主题和中英文提示；Electron 本地版在系统默认浏览器打开同一地址。

## 打开网页

GitHub 自动部署配置及操作步骤见 [跨仓库 GitHub Pages 部署说明](../.github/DEPLOYMENT.md)。向源码仓库 main 推送后，CI 测试并构建网页，再同步到 RealPixelArt/RealPixelArt.github.io 的 gh-pages 分支。

在项目根目录运行一个静态文件预览服务：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory web
```

浏览器访问 **http://127.0.0.1:8765/**。这里的 http.server 只发送静态文件，不执行图像处理；部署时可换成任何 HTTPS 静态托管，不需要 Python 服务。浏览器的 Worker / WASM 加载限制使得双击 `index.html` 的 `file://` 方式不适用。算法完整性校验需要安全上下文，请使用 localhost 或 HTTPS。

桌面端左侧为竖向参数栏，右侧并排显示“原图”和“恢复结果”；窄屏将参数栏移至图片下方。点击原图窗口或将文件拖入窗口即可选择、更换图片，也可使用窗口下方的 lastTour 示例；原图窗口支持 Enter / 空格键选图。“上传图片”和“生成”两个按钮作为一组在原图下方居中。网页默认勾选“生成处理过程”，生成后可查看网格、FFT、边缘等图像，并单独下载 ZIP；取消勾选可省去这些附加文件。ZIP 内路径为 `output/debug/<图片名>/`。浏览器只在点击下载后保存文件，不会直接写入电脑的 output 目录。Python CLI 仍默认关闭 debug。

页面打开即在后台初始化处理引擎，无需先选图或点击生成。初始化期间仍可上传、更换图片和调整参数；如果提前点击“生成”，任务等待同一次初始化完成后执行，不重复启动引擎。引擎启动、组件加载、就绪、图像处理、调色、导出和错误状态统一显示在**原图窗口的文件名下方、上传/生成按钮上方**。状态显示实际阶段，不伪造百分比。初始化失败后，选择图片并点击生成可重试。

“生成”在原图下方，其左侧提供同尺寸、同圆角的浅色“上传图片”按钮；“下载 PNG”在恢复结果下方。图片展示区在原布局基础上加高：桌面和平板增加 80px，手机增加 40px。恢复结果的图片区域下方直接显示“导出倍数”，不再显示单独的“— / PNG”信息行。网格仅自动识别，取色、透明度、局部调整直接显示；“更多设置”放最小/最大搜索间距、“强制正方形网格”、“生成处理过程”，以及“未识别网格时自动像素化”。“生成处理过程”和自动像素化仍默认勾选，方形网格默认不勾选。

默认开启“未识别网格时自动像素化”：先保护原生单像素细节、可靠插值网格和双向重复格距；没有可靠网格时，照片和不规则像素风图均生成保守尺寸的像素画，通常长边为 96–256，不再仅因边缘锐利而原样返回。已接受网格不会被这个尺寸预算进一步压粗，原生小图及透明画布上的小主体保留保护。自动生成的网格分数为 0，表示没有确认原始格子。关闭此开关可保留无网格输入。颜色后处理、导出倍数仍与网格解耦。

如果多个区域都有明显的水平／垂直边段，但全局网格评分不足，则先尝试边缘间距中位数估算，并继续使用原取色器。网页明确显示“已按方正边缘估算网格”，分数仍为 0；这不是已确认的原始格距。该回退复用现有核心，不增加库或 FFT，也不处理已被曲线证据否决的网格。关闭上述开关也会关闭此估算。详细规则和实测见 [README](../README.md#算法) 与 [评估](../EVALUATION.md)。

超过 400 万像素时，检测使用每方向最多 96 条完整长度的源分辨率扫描线，格距单位保持不变；不再执行整图二维 FFT。大图 `fft.png` 标明只显示中心最多 512×512 源像素区域的频谱，检测的一维投影仍覆盖完整横纵坐标。生成网格的平滑区域统计限制为每格 64 个样本，受支持的中心细线/高光可否决平均覆盖。已成功显示且方向尺寸匹配的普通输入复用浏览器原图预览，省去大图 PNG 重编码；算法仍读取原始文件字节。MPO 主照片及不可预览格式继续返回 Python 预览。详细规则见 [算法说明](../README.md#算法) 和 [评估记录](../EVALUATION.md)。

**颜色处理是独立的可选第二步**：默认不限制颜色数量、不启用色库。滑条左侧有“不限制”和“2”两个分开的停靠点，之后可选至 512 的每个整数；方向键逐个调整，Home 返回不限制，End 到达上限。勾选“使用色库”后，上限取该色库的实际不同 RGB 数，当前数量超出上限时自动收至上限，“不限制”仍表示不额外减少色库颜色。默认选择“DMC-436色”。另有 MARD 的 24、48、72、96、120、144、221、280 色规格；280 规格的当前源数据实际为 275 色，滑条上限也为 275。颜色模式提供“自然”（Lab/CIEDE2000）和“RGB”。

可以先生成再调整，也可以生成前设置颜色选项。改变数量、色库或颜色模式时，Worker 从缓存的**不限色原生 PNG**重新应用 `process_colors`，自动更新预览，不重新识别网格，也不在前一次限色结果上继续量化。关闭色库且恢复“不限定”可精确返回原生像素。alpha 始终保留。更新后的诊断 ZIP 同步颜色统计，网格/FFT 等图像不需要重算。自然模式计算量较高；颜色预算很小仍可能损失细节。

滑条“不限制”到“2”的间距为轨道的 20%。数量行右上角保留原字号、行高和右侧对齐位置：不限制时只显示文字；开启限制后，控件依次为“− 数值 +”，数值可直接编辑，两侧按钮逐个调整。按 Enter 或离开输入框应用输入；空值恢复上一次数量，越界值修正到 2–当前色库上限，小数取最近整数。数量行高度始终不变。

“生成”现在支持已规整的原生像素图。原始 bocchi2（1452×1083）仍恢复为 125×93；再上传 125×93 PNG 时会根据一像素细节保留原尺寸。此判断在共用 Python 核心中执行，不依赖文件名或元数据；真正的最近邻放大图仍正常恢复。颜色处理仍在网格识别之后执行。

恢复结果下方的导出滑条可选择 **1–16 中的所有整数倍**。生成时保留原生 PNG；滑条只更新导出尺寸，点击下载时才用同一 Python `export_png` 执行 Pillow 最近邻放大。不会重新提取特征、识别网格、取色或量化，不通过 Canvas 重编码，也不改变 alpha。预览仍显示原生结果；处理过程文件针对生成时的原生结果（1 倍），不会随导出倍数重新计算。

右上角两个图标分别切换明暗主题和中英文，偏好保存在 localStorage；存储不可用时仍能使用切换。首次默认跟随系统主题和浏览器语言（中文或英文）。主题、语言和导出倍数均不会让已生成的结果失效。

## 与 Python 共用一份算法

```text
src/realpixelart/*.py       唯一的算法源文件
src/realpixelart/palettes.json  共用的 9 个色库
          ↓ python web/build.py
web/core.zip               原样打包的 Python 核心 + 浏览器适配器
          ↓ 浏览器内 Web Worker / Pyodide
Config → pixelize → save_result
          ↓
PNG / 可选诊断 ZIP
```

没有用 JavaScript 另写近似 FFT、网格评分或取色逻辑。网页将原始上传文件的字节交给 Pillow；不经过 Canvas 解码、白底合成、压缩或缩放后再检测。EXIF、透明区域、网格回退、限色和最近邻导出沿用 Python 实现。

共用核心现增加水平／垂直连续边段辅助验证：仅在锐利但较弱的候选上检查至多 9 个原分辨率区域，多个区域一致反驳时才转入既有回退。强网格、原生像素与较软/稀疏证据保守处理；不增加参数或运行依赖。下载的处理过程 `info.json` 包含 `axis_segments`、被否决网格及 `grid_validation` 耗时。它不是独立的像素画分类器，详细规则和实测见项目 README/EVALUATION。

网页显示背景可切换透明棋盘、白色、深色，只影响预览。两个图片窗口各自右上角提供缩小、倍率、放大和“适应窗口”，仅在该窗口有可显示的图片时出现，未上传、未生成或移除图片后隐藏。加减按钮分别乘以 0.8 和 1.25，滚轮以指针位置为中心缩放。缩放范围通常是 1%–3200%，极大或极小图会扩展范围。两个窗口均可按住鼠标左键拖动图片，未放大时也可移动；移动达到 5 个 CSS 像素后判为拖动，松开不会弹出上传窗口，轻微手抖仍按单击处理。在窗口外松开也会结束拖动。图片移动范围保留少量可见区域，“适应窗口”恢复自动适配并居中。原图仍支持单击上传、Enter / 空格选图、拖入新文件。手机保留页面触摸滚动，图片平移目前使用鼠标。结果图在可放大时优先整数倍显示。CSS 像素化显示保持原始图片数据，平移和预览倍率不影响网格、颜色和导出尺寸。下载图片的倍数只由“导出倍数”决定。

### 修改后同步

1. 修改 `src/realpixelart` 中的算法或默认配置。
2. 运行 `python web/build.py`，更新 `core.zip`、`core-manifest.json`。
3. 运行 `python web/build.py --check`，确认网页包与源文件逐字节一致。
4. 刷新网页并运行浏览器回归。

manifest 的默认值取自 Python `Config`，色库名称与实际数量取自 `palette_catalog`，不在 JavaScript 另维护一份色库。新增参数时仍需增加相应控件；文案集中在 `i18n.js`。改变网格、取色等核心参数需要重新生成；颜色设置仅运行独立后处理，导出倍数只在下载时执行最近邻放大。

Worker 校验 core.zip 的 SHA256，避免缓存中混用两份算法。`build.py --check` 检查所有核心文件，包括诊断导出代码。不应直接编辑生成的 core.zip。

## 目录

| 文件 | 职责 |
|---|---|
| `index.html` / `styles.css` | 中文界面、桌面及手机布局 |
| `app.js` | 文件选择、参数、预览、下载、错误与取消处理 |
| `i18n.js` | 中英文静态文案、动态提示及无障碍标签；浏览器偏好读写 |
| `worker.js` | 在独立线程初始化运行环境，传递输入和结果，清理每次处理的临时文件 |
| `bridge.py` | 浏览器文件适配、调用现有 API、打包诊断，无网格/取色算法 |
| `build.py` | 开发期同步和可选运行时下载，不参与网站运行 |
| `core.zip` / `core-manifest.json` | 可重复生成的算法包、源文件哈希、默认配置 |
| `vendor/` | 本地运行时、NumPy / Pillow、资源哈希和许可证 |
| `assets/demo.png` | 从 input/lastTour.png 同步的实际示例 |
| `tests/verify.cjs` | 真实浏览器与桌面 Python 的对照测试 |

## 运行依赖与取舍

固定使用 Pyodide **0.26.4**，其 NumPy 为 **1.26.4**，与当前桌面环境相同；浏览器 Pillow 为 **10.2.0**，当前桌面为 **12.1.0**。选固定版本用于减少数值差异，后续升级需重跑一致性测试。

第三方运行文件约 **27.4 MiB**，加上示例与网页文件仍是纯静态资源。首次初始化比已启动的桌面 Python 慢，现在在页面打开时提前进行；后续复用同一个 Worker。提前初始化利用选图时间，不能消除首次下载和启动成本。取消会终止 Worker，下一次生成会重新初始化；旧 Worker 的迟到消息不会改变新任务状态。

运行时已下载，无需联网构建。仅首次重新获取这些文件时使用：

```powershell
python web/build.py --runtime
```

此命令访问官方发布 CDN 获取固定版本，校验 NumPy/Pillow wheel 的发布 SHA256，并记录资源清单。网页运行时只请求本站静态资源，不请求 CDN。测试工具 Playwright 只用于开发，不是网页依赖。

参考：[Pyodide 浏览器运行说明](https://pyodide.org/en/0.26.4/)、[Worker](https://pyodide.org/en/0.26.4/usage/webworker.html)、[固定版本的包列表](https://pyodide.org/en/0.26.4/usage/packages-in-pyodide.html)。第三方许可证位于 vendor/licenses，NumPy/Pillow wheel 内也保留了原许可证。

## 验证

先启动静态预览服务。将 Playwright 安装到你指定的开发工具目录（不属于部署文件）：

```powershell
npm install --prefix ../.web-test-tools playwright
python -m pip install -e ".[test]"
$env:PLAYWRIGHT_MODULE = (Resolve-Path ../.web-test-tools/node_modules/playwright).Path
node web/tests/verify.cjs
```

默认使用已安装的 Chrome；可用 `CHROME_PATH` 指定 Chromium 可执行文件，`TEST_URL` 指定预览地址，`PYTHON` 指定桌面 Python。测试包含：

- input 中 6 张实际图片及其去掉元数据后的原生输出重新上传。
- 125×93 bocchi2 的实际网页上传、生成、调色、下载，保留原尺寸与全部 RGBA，显示格距 1×1。
- lastTour 的 8/32/128/512 色、center/median 取色、方形网格、16 色和 3 倍导出。
- DMC 的自然/RGB 32 色及不限数量、MARD24 RGB、MARD280 自然 64 色，桌面与浏览器逐像素比较。
- 颜色设置切换不新增 process 请求；禁用色库并取消限色恢复不限色像素；二次调色与 Python 直接后处理一致；诊断 ZIP 内颜色信息同步更新。
- hollow-knight 的搜索范围限制、关闭局部漂移、二值 alpha（受限范围可能触发原尺寸回退）。
- 桌面/浏览器输出的全部 RGBA 像素、横纵切割线和启发式分数对照。
- 默认开启处理过程、开关和 ZIP 内容，损坏文件报错；原图窗口点击、键盘选图、拖入、更换和移除图片，示例、取消、重新生成、下载、参数过期状态；桌面左侧参数栏、手机参数在下方、双窗口并排。
- 两张图独立滚轮/加减缩放、适应窗口；右上角控件位置、上传/生成按钮尺寸与形状、窗口高度；缩放不修改导出倍数、图像字节和网格，不重新处理。
- 颜色滑条“不限制”到 2 的键盘步进、512 上限、9 个色库的实际上限、真实鼠标拖动、原位置与字号的数值编辑及加减按钮、空值和越界修正，以及调色过程中继续调整时最终应用最新值。
- 1–16 倍导出逐像素等于原生 RGBA 重复；滑条拖动、3 倍下载过程中没有新增 process 请求，原生预览、网格和处理耗时不变。
- 黑/白主题、中/英文切换及偏好保存；英文界面无残留中文正文；按钮位于对应图片下方，320 px 窄屏无页面横向溢出。
- 所有请求均为本站 GET，无图片上传及外部请求。
- 引擎在选图前自动启动；真实运行资源延迟加载时提前生成、初始化期间取消并重新生成、首次资源加载失败后重试，都能完成正常处理。引擎就绪消息不会提前解除任务锁定，重复生成复用同一引擎。桌面与窄屏状态栏位于原图文件名下方。
- 注入真实 Python MemoryError，验证网页释放旧 Worker、显示明确错误，并在下一次生成时重新初始化和正常完成处理。
- 无可靠网格的锐利图案自动像素化；超过 400 万像素的 40 倍整数格恢复和普通图片分支，与 Python 逐像素一致。另有真实网页 8256×5504 的计时及原图预览复用检查，记录在 output/debug/fast-fallback。

结果和截图写入 `web/tests/results/`。部署可排除 tests、build.py、bridge.py、README；保留 core.zip、manifest、前端文件、assets 和 vendor 即可。

### 本次实测结果

窗口尺寸另与修改前的页面实测值对照：1440×1100、1280×800、1000×900、390×844、320×740，分别用中英文验证。窗口总高度变化均为 0；图片区域分别增加 40/40/62/83/83 px；颜色数量行及右上角文字的位置和高度保持一致。记录见 [layout-geometry.json](tests/results/layout-geometry.json)。

34 组配置全部通过：输出的全部 RGBA 像素相同、切割线相同，启发式置信分数误差小于 1e-6。独立导出的 1–16 倍均与原生 RGBA 精确重复一致。网页切换色库、数量、模式、预览缩放与 3 倍下载均未增加网格处理请求；取消颜色限制后逐像素恢复不限色结果。处理过程 ZIP 在调色后同步更新颜色记录。所有网络请求均为本站 GET，未发生外部请求或图片上传。桌面、夜间英文及手机截图保存在 tests/results 中。Python 回归共 284 项通过，包含原有固定像素基准、512 色后处理、分块计算一致性、MPO 主照片选择及原尺寸回退。

各配置的桌面与浏览器实测耗时记录在 [verification.json](tests/results/verification.json)。此计时不包含首次引擎初始化、界面绘制、输入预览编码或下载；单次运行受机器负载影响。单独切换颜色只执行后处理，默认不启用颜色处理时不付出色库匹配成本。界面默认开启处理过程会额外生成网格和 FFT 等诊断图；纯算法测试中的 debug 开关以记录为准。

## 限制

- 同一算法不等于任意平台上所有文件都能保证位级一致。浏览器与桌面 Pillow/编解码器不同，JPEG 等格式及诊断文字绘制可能有差异；以记录下来的回归样本为已验证范围，不能把它解释成所有输入的保证。
- 文件不超过 64 MB；当前 Pyodide 引擎的 Wasm 堆上限为 2 GiB，文件体积不能代表解码后的占用。大图仍可能触及浏览器内存限制，不会偷偷缩小输入。已分块计算梯度、FFT 和图像转换，避免为诊断图构造全尺寸 RGB/完整镜像频谱；详见 [大图实测](../EVALUATION.md)。内存异常会释放 Worker，下一次生成可重新初始化。
- 单张静态图片；相机 `.jpg` 内嵌 MPO 多图时明确读取主照片（没有唯一主图标记时取第一张），并显示选择提示、保存实际格式和帧数。动画 GIF/APNG、多页 TIFF、批处理和透视网格仍不支持。
- 原有算法对 lastTour 的网格分数偏低，网页也如实显示。限色可能损失少量关键颜色，网页不额外修图或补线。
